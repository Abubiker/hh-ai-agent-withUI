# ТЗ на дизайн: HH Agent для macOS

Документ для дизайнера. Описывает продукт, все экраны и состояния, технические
ограничения реализации и требования к иконкам.

Текущий интерфейс — рабочий, но собран программистом «чтобы работало». Нужен
внятный дизайн: и по виду, и по структуре.

---

## 1. Что за продукт

Приложение для macOS, которое само ищет вакансии на hh.ru, отбирает подходящие
с помощью локальной ИИ-модели, пишет персональные сопроводительные письма и
отправляет отклики. Работает часами в фоне.

**Пользователь** — соискатель, чаще всего технический специалист. Запускает
приложение и уходит заниматься другими делами; периодически заглядывает
посмотреть, что происходит, и читает уведомления об откликах.

**Главный сценарий:** открыл → нажал «Запустить» → свернул → получает
уведомления → вечером посмотрел статистику.

**Второй по важности сценарий:** первичная настройка (резюме, запросы, модель).
Делается один раз, но именно на нём люди отваливаются, если непонятно.

**Эмоция, которую должен вызывать интерфейс:** спокойная уверенность, что
робот работает и ничего не сломает. Это инструмент для нервного процесса
(поиск работы), поэтому важна предсказуемость, а не яркость. При этом продукт
не корпоративный — он личный, чуть характерный.

## 2. Технические ограничения (обязательно к прочтению)

Интерфейс — **HTML + CSS + JavaScript внутри нативного окна WebKit**
(PyWebView). То есть верстается как веб-страница, но живёт как приложение.

Что из этого следует:

| Можно | Нельзя |
|---|---|
| Любой CSS: сетки, флексы, анимации, тени, скругления, `backdrop-filter` | Подключать шрифты, картинки и скрипты по ссылке из интернета — окно работает без сети |
| SVG-иконки прямо в разметке | Растровые ассеты «на глазок»: всё должно быть в 1x/2x или вектором |
| Системные шрифты macOS: SF Pro Text, SF Pro Display, SF Mono | Кастомные шрифты, если они не будут вложены в приложение файлом |
| Светлая и тёмная темы через `prefers-color-scheme` | Только одна тема — тёмная обязательна |
| Эмодзи как элемент оформления | Нативные элементы macOS (настоящие Cocoa-контролы недоступны) |

**Размеры окна:** по умолчанию 1080 × 760, минимум 880 × 620. Верстка должна
переживать растягивание до ~1600 px по ширине. Пользователь может менять размер.

**Единицы:** относительные (rem, %, fr). Жёстких пиксельных сеток лучше избегать.

**Шрифт по умолчанию** сейчас 13 px — это близко к нативному для macOS. Можно
менять, но с оглядкой: интерфейс информационно плотный.

## 3. Структура: что есть сейчас

Верхняя панель (постоянная) + 5 вкладок.

### Верхняя панель

Индикатор состояния, название, текущий статус, выбор длительности сеанса,
кнопки «Запустить» и «Остановить».

Состояния: `остановлен` / `работает` / `останавливается`.

### Вкладка «Работа» — главная

1. **Карточка готовности** (показывается только если что-то не настроено):
   список из 4-5 пунктов с отметками, кнопки «Установить браузер»,
   «Скачать Ollama», «Проверить снова».
2. **Статистика сеанса** — 9 счётчиков:
   - Просмотрено вакансий
   - Отсечено по стоп-словам
   - Прошли ИИ-фильтр
   - Отклонены ИИ
   - Написано сопроводительных
   - **Откликов отправлено** ← главная цифра
   - Уже был отклик (пропущено)
   - Страница не открылась (архив/капча)
   - Не удалось откликнуться
3. **Журнал** — поток строк в реальном времени, моноширинный, с автопрокруткой.
   Строк за сеанс — сотни. Есть обычные, предупреждения и ошибки.

### Вкладка «Резюме и поиск»

- Название резюме (короткое поле, должно совпадать с hh.ru посимвольно)
- Профиль для писем (большое многострочное поле, ~2000 символов)
- Поисковые запросы (многострочное, по запросу в строке, сейчас 4)
- Галка «Искать только в названии вакансии»

### Вкладка «Фильтры»

- Страниц на запрос (число), Пауза между кругами в минутах (число)
- Опыт работы — 4 чекбокса
- Регионы — многострочное поле в формате `Название | параметры`
  *(формат откровенно программистский, предложите человеческий вариант)*

### Вкладка «Модель»

- Выбор провайдера (3 варианта) + кнопка «Проверить» + строка результата
- Блок Ollama: адрес сервера, выпадающий список моделей, кнопка обновления
- Загрузка модели: поле ввода + кнопка + прогресс-бар со статусом
- Блоки для OpenAI-совместимого сервера и Anthropic (показывается только
  выбранный)

### Вкладка «Уведомления»

- Галки: рабочий стол, Telegram (раскрывает 2 поля)
- Кнопка «Проверить уведомления» + результат по каждому каналу
- «О чём сообщать» — 5 чекбоксов событий
- «Хранение токенов» — галка + пояснение
- Путь к файлу настроек + кнопка «Показать в Finder»

### Модальное окно капчи

Заголовок, пояснение, **скриншот страницы** (ширина произвольная, до 1200 px,
масштабируется), поле ввода, кнопки «Отправить» и «Пропустить вакансию».
Появляется неожиданно, блокирует работу агента — должно привлекать внимание,
но не выглядеть аварией.

## 4. Что не так с текущим дизайном

Честный список проблем, которые нужно решить:

1. **Пять вкладок, из которых четыре — настройки.** Настройки трогают один
   раз, а места занимают столько же, сколько работа. Возможно, стоит развести
   «работу» и «настройки» по разным уровням.
2. **Девять счётчиков без иерархии.** Все одинакового размера, хотя реально
   важен один — «Откликов отправлено». Остальное — диагностика.
3. **Журнал перегружен.** Технические строки вида
   `⏩ Пропускаем (Неподходящий грейд/профессия — 'lead'): QA Lead (Зеленоград)`
   вперемешку с важным «Отклик отправлен». Нужны уровни или фильтрация.
4. **Нет ощущения прогресса.** Пока агент работает, непонятно, на каком он
   этапе: какой запрос, какая страница, сколько осталось.
5. **Настройки сохраняются молча.** Пользователь не понимает, применилось ли.
6. **Ошибки выглядят как обычный текст** в журнале, легко пропустить.
7. **Формат регионов** (`Москва | &area=1`) — утечка технических деталей в
   интерфейс.
8. **Нет пустых состояний.** До первого запуска статистика — девять нулей,
   журнал пуст. Момент первого знакомства выглядит мёртвым.

## 5. Что нужно спроектировать

### 5.1. Экраны

Обязательно:

1. **Главный экран, агент остановлен** (первый запуск, ничего не настроено)
2. **Главный экран, агент остановлен** (всё настроено, есть статистика прошлого сеанса)
3. **Главный экран, агент работает** — с прогрессом и живым журналом
4. **Все экраны настроек** (резюме, фильтры, модель, уведомления)
5. **Модальное окно капчи**
6. **Загрузка модели** с прогрессом
7. **Состояние ошибки** — модель недоступна / нет интернета / HH блокирует

Желательно:

8. Свёрнутое/компактное состояние — если предложите идею «мини-окна»
9. Меню в строке меню (вид выпадающего меню)

### 5.2. Состояния элементов

Для каждого интерактивного элемента: обычное, наведение, нажатие,
недоступное, с фокусом (клавиатурная навигация обязательна).

### 5.3. Цветовая система

Нужны токены под светлую и тёмную темы: фон, поверхность карточки, границы,
основной и второстепенный текст, акцент, успех, предупреждение, ошибка, фон
журнала.

Учтите: акцентный цвет в macOS пользователь меняет в системных настройках.
Решите, следуем ли мы за системным акцентом или держим свой.

### 5.4. Типографика

Шкала размеров и насыщенностей: заголовки карточек, основной текст,
второстепенный текст, цифры счётчиков, моноширинный журнал.

## 6. Иконки

### 6.1. Иконка приложения

Главный ассет. Сейчас — синий квадрат с галочкой, сделан программно, заглушка.

**Требования:**
- Формат macOS: скруглённый квадрат в сетке Apple (Big Sur и новее), с полями
- Размеры: 16, 32, 64, 128, 256, 512, 1024 px (каждый в 1x и 2x)
- Отдаётся набором PNG (соберём в `.icns` сами) или как исходник Sketch/Figma
- Должна читаться в 16 px в Dock и в списке «Программы»
- Не должна выглядеть корпоративной или похожей на иконку hh.ru (не наш бренд)

**Смысл:** автоматизация поиска работы. Возможные направления — робот-помощник,
отправленное письмо, движение вперёд. Не буквальный портфель и не рукопожатие.

### 6.2. Иконка в строке меню

Отдельный ассет, **не уменьшенная копия основной**.

- Монохромная «template»-иконка: только чёрный и альфа-канал. macOS сама
  перекрашивает под светлую и тёмную строку меню
- Размеры: 16 × 16 и 32 × 32 (для Retina), формат PNG с прозрачностью
- Нужны **два состояния**: агент остановлен и агент работает
  (различие должно читаться в 16 px, не только цветом — в template-режиме
  цвета нет)
- Опционально: 2-3 кадра для анимации «работает»

### 6.3. Прочая графика

- Пустое состояние журнала и статистики (иллюстрация или явно ничего)
- Набор иконок интерфейса: запуск, остановка, настройки, проверка, загрузка,
  предупреждение, ошибка. Только SVG
- Оформление окна DMG при установке (фон с подсказкой «перетащите в
  Программы») — 600 × 400

## 7. Формат сдачи

1. **Figma-файл** с макетами, разобранный на компоненты, отдельные фреймы для
   светлой и тёмной темы
2. **Токены** цветов и типографики — списком, готовым перенести в CSS-переменные
3. **Иконки** — PNG-набор всех размеров + исходники в векторе
4. **SVG интерфейсных иконок** — оптимизированные, без лишних атрибутов
5. **Краткое описание решений**: почему такая структура, что изменили и зачем

Отдельно попрошу: если предлагаете структурные изменения (например, убрать
вкладки или объединить экраны) — покажите текущий и предлагаемый вариант рядом,
чтобы можно было сравнить.

## 8. Полезный контекст

**Реальные данные для макетов** — используйте их, а не «Lorem ipsum»:

Строки журнала:
```
🔍 Поиск по запросу: Тестировщик
📍 Режим: Москва (любой график)
📄 Парсим страницу 1 по запросу 'Тестировщик' (Москва (любой график))...
⏩ Пропускаем (Неподходящий грейд/профессия — 'lead'): Senior / Lead QA Engineer
👁️ Открываем вакансию: Специалист по тестированию
✨ Вакансия подходит: Специалист по тестированию
✅ Отклик отправлен: Специалист по тестированию
❌ ИИ отклонил: Инженер по нагрузочному тестированию
🔒 HH показал проверку VPN — нажимаю «Я не использую VPN»...
😴 Круг закончен. Жду 10 мин до следующего.
```

Названия вакансий бывают очень длинными:
`Teamlead QA Engineer/ Руководитель команды тестирования в TravelTech`

Типичные цифры за сеанс: просмотрено 40, отсечено 28, откликов 3-8.

**Замеренные тайминги** (нужны для проектирования индикаторов):
- проверка вакансии моделью — 0.3 с
- написание письма — 12.6 с ← здесь нужен явный индикатор, это долго
- открытие страницы вакансии — 4 с
- пауза между кругами — 10 минут по умолчанию

**Текущая реализация** для справки:
`ui/index.html` — вся вёрстка и стили в одном файле, ~600 строк.
Можно смотреть как на прототип структуры и на список того, что должно быть.

### Как посмотреть интерфейс живьём, без установки приложения

В папке `ui/` есть режим предпросмотра с реалистичными данными. Нужен только
браузер и одна команда в Терминале (Python есть в macOS по умолчанию):

```bash
cd путь/до/проекта/ui
python3 -m http.server 8777
```

Затем открыть в браузере: **http://localhost:8777/index.html?mock=1**

Что доступно в этом режиме:

- все вкладки заполнены настоящими данными (запросы, резюме, статистика);
- кнопка **«Запустить»** проигрывает работу агента: журнал наполняется
  строками, включая предупреждения и ошибки;
- кнопка **«Скачать»** на вкладке «Модель» показывает прогресс загрузки;
- окно капчи вызывается из консоли браузера командой `showCaptchaDemo()`;
- тёмная тема включается сменой оформления macOS
  (Системные настройки → Оформление).

Параметр `?mock=1` обязателен — без него подставятся пустые данные.

Чтобы посмотреть, как это выглядит в настоящем окне приложения, попросите
собрать DMG — но для работы над дизайном достаточно браузера.

## 9. Границы задачи

- Логику и тексты сообщений менять можно и нужно предлагать, но
  переформулировки согласуем отдельно
- Windows-версия не проектируется (код кроссплатформенный, но сборка только
  под macOS)
- Онбординг-туториал со слайдами не нужен — достаточно понятной карточки
  готовности
- Локализация только русская
